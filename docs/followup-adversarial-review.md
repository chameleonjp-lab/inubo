検証では、正しくない操作でも成功してしまう条件、操作できない技を合格扱いにする条件、既存記録への影響、実装者が決められない契約、確認用配信の不備を探した。新たなゲームコードの試験、実データベースへの送信、iPhoneの操作は行っていない。

## 3. 対象外と判断したこと

| 論点 | 扱いと理由 |
|---|---|
| 38技の競技導入、実験場掲載 | 現行の保留範囲を維持する。競技の配点・公開記録の扱いまで変わるため、本計画へ混ぜない。 |
| 犬種の性能値の即時変更 | 実測と評価までを対象とする。変更が必要なら版を分ける別PRを作る。 |
| 翻訳文そのものの正しさ | 辞書は未実装。キーの一致だけでは文章の自然さや意味を保証できないため、実装後に別途確認する。 |
| 本番データベースの現時点の合否 | 今回は本番を操作していない。ソースや過去の公開記録だけで現在の受付結果を合格と断定しない。 |
| iPhoneの操作・音・表示の合格 | 実機記録は未取得。確認方法を具体化したことと、実機で合格したことを分ける。 |

## 4. 修正版の再確認

最初の再確認ではR01〜R10・R12の対応を確認した。R11について、手すり区間の終点で`f2-rail`から`late`へ移るため、刻み後の経路名だけを読むと正常な通過を失敗にし得る、という追加指摘があった。

これを受け、計測データへ刻み内の経路遷移を追加した。正常な終端通過は途中離脱の失敗より先に終了を確定し、正常通過・別経路・途中離脱・失敗後の再進入を別々に試すよう修正した。修正後のF09を独立担当が再確認し、R11を含む全12件について、計画段階として対応済み・計画書としてPR可能との判定を得た。

文書6ファイルについて、相対リンク、工程F00〜F09と指摘R01〜R12の欠番・重複、文字コード、末尾改行、余分な行末空白を確認した。既存4文書の変更は後続計画へのリンクと現状の注記であり、過去の未実施欄を合格へ変更していない。新しいゲームコードは作成していないため、この作業でゲームの試験を実行・合格したとは扱わない。
