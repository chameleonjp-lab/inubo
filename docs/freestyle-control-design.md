# イヌボー 自由操作と着地判定の設計

2026年11月14日。基準ソースは `222ed247f84eb4b6f6150eff62974b43e06994df`（後続計画のPR #10取り込み後）。この文書はユーザーの「スワイプした通りに動かし、その結果から技と点を決める」という変更を要件にする。コードの実装・実機での合格は今後の作業である。

## 1. 決まった動作を出す仕組みから変更する

現行の`src/input/gestures.ts`は空中の軌跡を円・直線へ分類し、`src/game/tricks.ts`の`makeRotation`が回転方向・360°・所要時間を決める。競技は最大2枠を使い、技の練習も`LabSetup`に回転目標を先に指定している。点を着地で計算していても、その前の動作が定型になっている。

今回の要件は、入力中から犬と人の向きが連続して変わり、途中で止める・戻す・違う向きへ続けることができること。空中で名前付きの技を選ぶ処理、円や線の完成待ち、決まった角度までの自動回転は自由操作へ持ち込まない。

| ID | ユーザーから受けた要件 | 合格の意味 |
|---|---|---|
| U01 | スワイプした通りに動かす | 指を離す前から姿勢が変わり、同じ軌跡を途中で打ち切ると途中の角度で止められる。 |
| U02 | 空中で自由に動かす | 向き・回転量・回転順を途中で変えられる。8方向、360°、2枠、38技の一覧が操作の制限にならない。 |
| U03 | 動いた結果から技を判定する | 実際の姿勢と接触履歴が同じなら、選んだ見本や操作の名前にかかわらず同じ判定になる。 |
| U04 | 着地時点で技と点を決める | 最初の接地より後の回転・入力を、着地前に行った技へ加えない。空中の表示値は予定値とする。 |
| U05 | 実在しない技も可能にする | 既知の38技に一致しなくても、実際に動いて無事に着地できれば成立し、動作量に応じた得点を得られる。 |

以下の操作方法、離した後の挙動、配点は、上記を実装するための初期提案であり、ユーザーが数値や操作の詳細まで選択したという意味ではない。実装後のiPhoneでの確認で操作感を評価する。

## 2. 操作の初期案

画面に見えない球を指で回すように、なぞった経路から連続した3次元の向きの変化を作る。操作対象は「一緒」「犬」「人」をタップで選ぶ。初期値は「一緒」。技名や回転角を選ぶ操作は置かない。つかむ・はなす・足を戻す等は実際の接触を変える操作として残す。

この方式は小さな動き、斜め、曲線、反転をそのまま使える。比較した別案は、払う速さを回転速度にして指を離した後も慣性を残す方式である。初期案は、指を離した後に新たな回転を足さず、その時点の向きを保つ。慣性方式の採用は操作感を確認した後の変更候補とし、定型回転へ置き換えない。

### 入力と向きの対応

- 操作面の中央を球の中心、半径を操作面の短辺の0.45倍とする。指の位置を中心からの`u, v`へ正規化する。球の内側は`P=(u,v,sqrt(1-u²-v²))`、外側は`P=normalize(u,v,0)`へ投影する。画面上方向を`+v`とする。外周では円をなぞって回転を続けられ、指を置き直して続きを操作できる。
- 直前と現在の投影点を結ぶ回転を、犬・人の実際の姿勢へ順に適用する。球の反対側へ一度に移る場合も、画面上の区間を途中の点で分けて向きを求める。最短回転の端点だけから回転方向を推測しない。
- 1区間の変化を最大15°になるまで分割し、各区間の軸・符号・角度・時刻を記録する。この15°は軌跡を計算する細かさであり、姿勢を15°へ丸める値ではない。最終的な17°・225°等もそのまま表示・判定に使う。
- 球の座標を世界へ移す基準は、踏切時の道の向きと上方向から計算側で固定する。描画カメラの前フレームの向きを入力へ戻さない。空中のカメラの向きもこの基準に合わせ、位置だけを追従させる。

各指は触れ始めた時点の操作対象を保持する。対象ボタンの変更は次に触れる指から有効にし、既に触れている指の対象を途中で入れ替えない。犬・人の各対象を同時に操作できる指は1本ずつ。「一緒」は両方が空いている場合だけ操作を始められる。同じ対象を2本目が奪って姿勢を二重に回さない。犬と人へ別々の指を使う操作は任意で、1本の指で対象を切り替えて順に動かすこともできる。

地上の左右移動と踏切は引き続き位置・速度へ作用する。踏切に使った指は、そのまま空中回転へ流用せず、一度離してから新しい操作を受ける。ボタン操作でも同じ入力経路を通す。新ルールでは空中の`updateAttitude`による自動整列を止め、描画でも道の傾きや旧`basePitch`をもう一度掛けない。指を離した後の世界姿勢は、実際の接触による変化を除いて維持する。回転不足を自動で補う処理は作らない。

支持中にも同じ操作面から回転を受ける。入力の単位を空中のjumpIdに限定せず、`MotionEpoch`（空中または支持中の操作区間）のIDを使う。空中は踏切時、支持中はその支持へ入った時に道の接線と面の法線から基準を固定する。技29のように縁へ掛かった状態で向きを変える場合も、指で回転を始め、その結果として支持が残るか・外れるかを調べる。抜けるボタンが決まった半回転を代行することはしない。

## 3. 実際に動いた姿勢を共通の記録にする

犬と人の世界座標の姿勢をそれぞれ`qDogWorld`・`qRiderWorld`として持つ。3次元の回転を途中の向きでも安定して表す値（四元数、Quaternion）を使い、入力のたびに正規化する。犬だけを回したときに人まで回ったり、「一緒」で同じ回転を二度足したりしない。描画の親子構造へ渡す相対姿勢は、世界姿勢から逆算する。

向きに加え、犬の胴体中心と人の腰の世界位置を持つ。空中の「一緒」は、従来の足元基準点の0.75m上に置く共通支点を中心に、両者の位置と向きを一緒に回す。「犬」は犬の胴体中心、「人」は人の腰を支点にする。支持中の「一緒」は実際の支持点を共通支点にする。どの場合も`position'=pivot+delta×(position-pivot)`と姿勢の更新を同じ計算で行い、身体が通る場所も接触へ渡す。この支点の値は初期案であり、質量中心を実測した値ではない。

重力と道に沿う進行は共通の移動基準点へ作用する。回転だけで進行時計やゴール判定の基準点を前へずらさない。足を戻す操作は、実際に足置きへ届く場合だけ接触を作り、腰や犬を即座に正解位置へ移さない。新ルールの競技と練習には同じ共通モデル・支点・接触形状を使い、旧記録の再生には旧モデルを使う。

姿勢の最終値だけでは0°と360°と720°を区別できないため、実際に適用した小区間の回転履歴も保持する。ボタンの種類や「狙った技」は履歴の得点源にしない。接触で制限された場合は、要求した向きと実際に通った向きを区別する。つかんでいた持ち手へ届かなくなった場合は解除を記録し、腕を伸ばしたことにして保持を続けない。

空中の自由回転は競技と練習で同じ計算を使う。移動の重力、地形、保持・接触、手足の到達可能性は既存の後続計画F01・F02を使う。全身の見た目だけを動かして当たり判定を旧姿勢に残す実装は合格にしない。

空中区間だけでなく、片側支持・レール・曲面の接触区間も時系列に残す。地上で始まる05・06・25、支持中に回る29、空中から縁へ戻る31も、回転と支持の前後関係から名前と目標達成を判定する。空中以外の履歴を着地のたびに捨てない。

## 4. 着地の判定と確定時刻

最初の接地時刻を`cutoffUs`とし、空中履歴をその時点で閉じる。同時刻は衝突・転倒→支持と回転履歴の集計→自然な接触→空中履歴の固定→その時刻の入力、の順で処理する。自然な接地と同時の空中入力は使わない。

指による回転は適用時刻の空間的な経路としても接触検査する。同じ時刻の大きな移動や遅れて届いた複数点でも、`inputSeq`と経路上の`pathProgress`で通った順を定める。入力の途中で初めて接地した場合は`cutoff={atUs,inputSeq,pathProgress}`を保存し、その手前までの実動作だけを含め、残りを止める。位置を過去の時刻へ補間して、既に確定した着地を変更しない。時間差0の経路から保持時間や滑走距離は増やさない。

着地の成立は実際の支持部位、接触面のつながり、足と足置き、手の解除、犬の上方向と面の法線を調べる。既存の30°以内を普通の着地、10°以内をきれいな着地の初期値として使う。進行方向に対する水平の向きは任意とし、0°・180°への一致や「1回転が完了したか」は着地の条件にしない。回転を途中で戻した結果も、その時点の姿勢で判定する。

接触のまとまりと安定を確かめる条件はF02の40ミリ秒、150ミリ秒・0.2mを使う。最初の接地で技の履歴と採点元を固定し、確認中は予定得点を表示する。無事な着地が確かめられた時に1回だけ点を確定し、失敗なら0点とする。この確認中の操作は次の地上動作であり、閉じた空中技を追加回転で救済しない。

採点先の`pathId/sectionKey/opp`は最初の接地位置で固定する。確認中に区間を出ても現在位置へ付け替えず、その採点機会の通過漏れ処理だけを保留する。得点確定・失敗が決まった後に、保留した区間退出を元の時刻順に処理する。安定条件より先に再び跳んだ場合、次のジャンプは自由に始められるが、直前の未成立の着地は0点で閉じる。新しいジャンプで前の保留情報を上書きしない。

同時刻は安定条件の成立→区間退出→ゴール→新しい入力の順に処理する。安定成立と同時のゴールには確定点を含め、ゴール時点で未確認の着地は0点で閉じて後から加えない。これは確認待ちを採点履歴の変更に使わせないための規則である。

ゴールでは、その時点までに成立確認が済んだ得点を使う。確認中の着地や、空中でゴールを越した後の動きは加えない。これは現行の「ゴールまでに着地済みの技だけを確定する」順序を保つための初期案である。結果には予定値と確定値を混ぜない。

空中→レール→再び空中は、レールへの支持を一つの着地として区切る。技の結果は空中区間ごとに作り、レールの距離点は滑り終えた後の安全確認で別に確定する。IDを使い、同じ着地通知で繰り返し加点しない。

## 5. 技名は後から付け、名前がなくても採点する

判定は二つに分ける。成立と得点を実際の運動・着地から計算し、その後で38技の参考条件と照合して名前を付ける。名前の一致は得点計算の入力にしない。辞典を無効にした場合でも姿勢、着地結果、点は変わらない。

既知の技に一致すればその名称を表示する。複数候補なら接触の特徴が具体的なものを優先し、構成する動きを併記できる。どの技にも一致しない場合は「フリースタイル」と、実際に行った回転や保持を表示する。実在する技の名前を推測して付けない。発見の記録や名称を付ける機能は今回追加しない。

練習の標準は自由練習とする。38技の選択は任意の見本・目標であり、選んだ技と違う動きでも無事な着地は成立する。「着地成功・別の動き」と「見本の目標達成」を別に表示する。準備欄から回転目標・指定角・自動脱出の選択を外し、構え、地形、手の選択など実際の操作に必要な項目を残す。

## 6. 自由な動きを採点する初期案

名前のない動きにも共通して使えるよう、犬と人の実際の回転量を測る。配点の数値は提案であり、旧記録の配点と同じとは扱わない。

固定軸の小回転ベクトルの加算や、軸別のねじれの読取を切り替える式は使わない。任意の軸の1回転が違う点になったり、小さな閉路だけで読取値が増えたりする反例があるためである。初期案は、実際の姿勢が一定以上変わった回数を数える単純な方式とする。

1. 犬・人それぞれについて、踏切時の実姿勢を基準qAnchorにする。実際の姿勢経路を最大15°以下の小区間の順に読む。最終姿勢だけにして周回を失わない。
2. 基準姿勢との角距離は`d=2×acos(clamp(abs(dot(qAnchor,q)),0,1))`で測る。実際の経路上で初めて45°へ達した地点を探し、45°分を加算して、その地点を次の基準qAnchorとする。残る経路も同じように処理する。入力の区切りで基準を初期化しない。
3. 経路の途中で45°を越えて戻る場合も、区間の最大変化を調べて最初の到達を見つける。到達点は経路の補間で求め、角度の検査許容差を0.000001°とする。45°未満の端数は次の入力へ持ち越すが、着地時には加点しない。
4. 有効回転Cを`45°×到達回数`とする。戻す回転も実際の運動なので数える。45°以上を往復する動きの完全な反復対策はこの方式では保証しない。基準から45°に満たない小さな揺れだけでは、回数を増やさない。

犬の基礎点は`100×C犬/360`、人は`150×C人/360`、合計を最後に切り捨てる。45°は採点の区切りであり、操作や表示姿勢を45°へ丸める値ではない。任意の固定軸で犬を1回転すると100点。「一緒」で両方を1回転させると犬100＋人150＝250点になる提案である。旧版の定型技150点とは別の配点である。

| 実際に動いた例 | 倍率を掛ける前の基礎点 | 判定上の意味 |
|---|---:|---|
| 犬だけ同じ軸で360° | 100 | 1回転の履歴を持ち、最終姿勢が0°でも点が残る。 |
| 犬だけ720° | 200 | 2回転を0°へ丸めて失わない。 |
| 犬と人が同じ軸で225°ずつ | 156 | 既知名がなくても実際の角度から点を計算する。 |
| 犬が＋360°の後に−360° | 200 | 姿勢は元へ戻っても、実際に行った2回転分を数える。 |

普通の着地は1倍、きれいな着地は1.2倍、失敗は0倍とし、倍率後も切り捨てる。姿勢と接触が成立していれば、半回転や斜めの未知の組合せを「回転不足」という理由だけで失敗にしない。基準から45°に達しない小さな動きだけなら、着地に成功しても回転の得点は0の場合がある。Cの集計は当該空中区間の踏切からcutoffまでとし、支持中の回転は時系列と命名に残す。

グラブは空中での実保持が120ミリ秒以上あり、着地前に離れた場合に50点を1回だけ加える。持ち替え・同じ持ち手の連打は増点しない。地上で持つ35・足を着く36等の名前に固定ボーナスは付けない。レールは既存の1m10点・1本100点、連続成功は3区間100点、採点機会ごとに最初の有効な着地だけを得点化する。技点上限5,000・タイム点上限5,000・総合10,000は初期版では維持する。

ここで採点機会を消費する「有効な着地」は、無事な着地が成立し、回転と空中グラブの合計が1点以上あるものとする。無操作や小さな動きだけの0点着地は成功表示できるが、採点機会を消費せず、連続成功数も増やさない。未採点のまま区間を出た場合は従来どおり連続数を切る。名前がないことでは採点対象から外さない。地上の荷重維持・曲面の静止は履歴と見本の達成判定に使い、初期版ではその名称だけのボーナスを付けない。

## 7. 新旧記録と実装順

コースは公園`park-2`を使い、新しいルール識別値を`rules-freestyle-1`とする。旧`rules-1`と最高点・最速・順位・再生を混ぜず、旧記録と送信待ちは維持する。新しい受付が用意される前に新ルールの点を旧ルールとして送ることはしない。

まず隔離した確認版で入力→姿勢→着地→名前・点という一巡を、競技と練習の両方で試す。38技の図鑑を作り込む作業より先にこの一巡を確認する。詳細は[自由操作の実装計画](freestyle-implementation-plan.md)。15言語・確認用配信・旧記録保全等の共通作業は[後続計画](followup-implementation-plan.md)を使う。

## 8. 確認に使った資料

現行の動作は基準コミットの[軌跡認識](../src/input/gestures.ts)、[定型回転と採点](../src/game/tricks.ts)、[着地処理](../src/game/scoring.ts)で確認した。

回転値の正規化・積の順序・方向ベクトル間の回転は[Three.jsの公式説明](https://threejs.org/docs/pages/Quaternion.html)、回転の再変換で周回数を失う点は[Eulerの公式説明](https://threejs.org/docs/pages/Euler.html)を確認した。入力の細かな経路は[MDNのgetCoalescedEventsの説明](https://developer.mozilla.org/en-US/docs/Web/API/PointerEvent/getCoalescedEvents)を参照し、利用可否を調べてから使う。利用できない端末でも通常のpointermoveで操作できるようにする。上の入力対応と配点は資料の引用ではなく、本プロジェクトの設計案である。
