# 犬のスケボー（inubo）実装計画書

2026年11月7日・初版。根拠は[要件仕様書](game-requirements.md)。目標は、3種の犬で3コースを完走でき、同じ走行から総合点とタイムの自己ベストを正しく残せること。チェック欄は**これからゲームを実装するときの作業**を示す。

## 1. 進め方と作る順番

最初に公園の「直線→階段と手すりの分岐→合流→ゴール」を通して作る。犬・視点・複合入力をここで実際に試す。次に3コースと3犬種に広げ、演出・記録・公開時の連携を足す。資料作成時のリポジトリには既存のゲームコードがないため、以下は作成予定のファイル名と技術構成である。

**実装上の選定案。** ブラウザで動く型付きのJavaScript（TypeScript）で計算をまとめ、犬・人物・コースは立体描画ライブラリのThree.jsで描く。Viteで静的配信用にまとめる。入力・接触・採点は画面描画から切り離し、計算だけをVitest、画面の一連の流れをPlaywrightで確認する。端末の操作感と聞こえ方の合否はiPhone 17 ProのSafariで取る。依存ライブラリの版は採用時に固定する。

| 工程 | 先に必要な工程 | その工程の完了時にできること |
|---|---|---|
| P01 時計と画面 | なし | ホームから仮コースを開始・停止・再開・完走できる |
| P02 道と衝突 | P01 | 坂・カーブ・壁・落下を実際に走り、停止位置から脱出できる |
| P03 指と回転 | P01。P02の完成前は固定の踏切を使う | 片手でも両手でも同じ複合技を決められる |
| P04 手すりと採点 | P02・P03 | 公園の二つの走り方で得点と最速が分かれる |
| P05 コース・犬種・アイテム | P02。完成判定にはP04も必要 | 3犬種×3コースがそろい、速さと経路の違いを試せる |
| P06 全行動の演出 | P01の出来事一覧から着手。P02〜P05で結合 | 絵・文字・音で24場面を見分けられる |
| P07 練習と端末内の記録 | P03・P04。コース固有部分はP05 | 練習・再挑戦・最速再生・共有を通せる |
| P08 公開用の順位 | P04・P07 | 試験用の接続先で2種の順位と通信再試行を検証できる |
| P09 実機・公開前判定 | P01〜P08 | 実測を残し、ゲーム部分と外部公開の可否を別々に判断できる |

## 2. 共通で使うデータと判定順

| 受け渡すもの | 入る値と使う側 |
|---|---|
| 走行の識別情報 | 1走に一度発行する `runId`、`courseId`、コース配置の版 `courseVersion`、採点・操作の版 `rulesVersion`、`dogId`、競技／練習、開始時の登録名・参加可否。再挑戦は新しい走行を作り、中断からの再開と通信再送は同じ走行を使う。 |
| 進路と時刻 | コース内の道・区間・手すり・アイテムに版内で安定した識別子を付ける。入力・接触・効果の時刻は同じ走行時計で持つ。動きは一定の刻みで更新し、刻みの途中で物を越えた場合も通過時刻を求める。画面の描画回数を時間・距離・得点の単位にしない。 |
| 接触と技の出来事 | `runId`、出来事番号、発生時刻、場所、ジャンプまたは手すりの識別子、種類、結果。計算側で1回発行し、音や表示はそれを読む。消音や粒の省略で成績は変わらない。 |
| 確定結果 | ゴールで版・コース・犬・完走時刻・タイム点・確定技点・総合点・区間別の内訳を固定。結果画面・保存・共有・順位送信は同じ内容を受け取る。最速と最高スコアは異なる走行を指せる。 |

走行中の同じ更新では、実際に触れた時刻順に処理する。同時刻に安全な着地とゴールがあれば、着地した技・降りた手すり・連続点を確定し、それから結果を閉じる。ゴール後に届いた着地・入力・演出終了から得点を変えない。中断時は進行中の物理状態と確定済みの角度を保存し、描きかけの指だけを破棄する。

**工程をまたぐ受け渡し。** 次は実装用の関数名・入出力案。入力の時刻は走行中の整数マイクロ秒 `atUs`。端末の時計表示や描画フレーム番号では順番を決めない。

| 用意する工程 | 受け渡す呼出し | 値の使い道 |
|---|---|---|
| P01・P02 | `advanceRun(state, untilUs, orderedInputs) → {state, events}` | P02は効果終了・物への最初の接触でその刻みを分割する。停止後の経路で残りの接触を求め直し、P04・P06に確定した出来事だけを渡す。 |
| P03 | `classifyAirStroke(samples, jumpId) → candidate`、`resolveTricks(candidates, atUs) → rotations` | 軌跡には指番号、開始・末尾時刻、円の閉点を持たせる。回転には犬・体、方向、開始時刻、枠数を持たせる。 |
| P04 | `settleLanding(run, contact) → scoreEvents`、`finishRun(run, atUs) → result` | 接地点で1個の区間・1個の着地を決める。走行中の距離は整数ミリメートルで保持。結果だけを100分の1秒に変換する。 |
| P07・P08 | `saveLocalResult(result, replay)`、`submitFinishedRun(startSnapshot, result)` | 端末内の最高・最速と公開先への送信を分ける。公開は1走1件を元に総合・タイムの両方を集計する。 |

### P03　指の軌跡、犬と人の回転

**担当する要件**　R11、R13、R14、R15、R16、R17、R18、R19、R20、R38。

- [x] `src/input/gestures.ts`は指ごとの開始・移動・終了・取消、取得時刻、縦横を保持する。離陸の指を消費し、円の閉じたところで線を切る。直線は離した時に8方向に分類する。判定距離は描画解像度と分け、画面の短辺に対する比率で調整する。
- [x] 角度は画面の上を0度として時計回り、各方向を「中心－22.5度を含み、中心＋22.5度を含まない」とする。簡単なタップ、円の始点と終点が離れすぎた曲線、地上の下払いはいずれも対応する技なし。操作面でだけブラウザのパン・拡大との競合を抑え、取消通知では該当の指の未確定部分を消す。
- [x] 2本指は先に成立した側を仮置きし、両方が有効になった同じ時刻から双方を回す。相方が取消・未成立なら空中の有効な単独技だけを一度開始。片手は円の閉点から犬を回し、線を離した時刻が回転完了の直前／同時／直後の順に、複合加点100／0／0。指を離す速さで二つの描き方の満点が変わらない踏切を用意する。
- [x] `src/game/tricks.ts`は1ジャンプにつき2枠と、犬・体それぞれの予定の回転量を持つ。2本の軌跡の時間が重なれば認識順を入れ替えても同じ結果にする。1本で閉じた円に線が続く場合の開始点は円の終点。二つの技を重ねる期間を用意し、同じ踏切から片手でも決められるようにする。
- [x] 犬の回転と人犬共通の回転を別に描き、地上では4本の足を使う。着地は重力の向きだけでなく、その接地面と予定の回転の残りで判定する。

### P04　手すりと採点

**担当する要件**　R25、R51、R52、R53、R54、R55、R56、R57、R58、R60。

- [x] `src/game/rails.ts`で、上から乗る・滑る・前へ跳ぶ・末端から降りる・側面衝突を扱う。足元が最初に触れた時刻で上面と側面を判別する。手すりに乗ったときは直前の空中技を確定し、手すりの距離は降りて無事に着くまで別に保留する。

- [x] 時刻は接触の前後を決めるまでマイクロ秒で保持。完走の記録値だけ `floor((elapsedUs + 5_000) / 10_000)` で百分秒にする。着地姿勢は回転前後を区別できる累積回転量で測る。区間は着地時の足元中心を開始線込み・終了線除外で判定し、選んだ経路の次の採点機会だけを連続成功の対象にする。左右の同じ採点機会の分岐には共通の機会番号を付ける。
- [x] 手すりから別の手すり上に無事に着いたら、前の手すりと到着時の空中技を先に確定してから、新しい手すりの距離を0から保留する。以前の区間・得点済み手すり・同じ着地通知を再処理しても既得点・連続数は増えない。

### P09　iPhoneで測り、公開できる版を決める

## 5. 変更を確認する単位

作業ごとに対象の試験を先に失敗させ、修正後は同じ試験で成功を確認する。ふだんの変更は該当工程の試験だけを回す。共通時計・入力契約・採点版・記録形式を変えた場合は、それを利用する後続工程の試験も実行する。計算の試験、画面の試験、ビルドは依存がなければ並行してよい。リリース候補では全計算試験・本番用ビルド・主要画面の通し試験・実機確認をそろえる。作業ブランチからPRを出し、マージは本人が行う。
