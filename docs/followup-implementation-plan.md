> **実装担当へ:** `superpowers:executing-plans` または `superpowers:subagent-driven-development` を使い、各工程のチェック欄と合格条件に沿って進める。本書は計画であり、未実装・未検証の項目を完了扱いにしない。

**目的:** 38技の見た目と接触を一致させ、画面から操作できることを確認し、既存の競技・記録を保ったまま15言語対応とiPhoneでの確認を完了する。

## 4. F01 — 判定と表示が共有する姿勢を作る

**作成:** `src/game/lab-geometry.ts`、`src/game/lab-pose.ts`、`src/view/lab-rig.ts`、`tests/lab-pose.test.ts`、`tests/lab-rig.test.ts`。**変更:** `src/game/trick-lab.ts`、`src/view/trick-lab.ts`、`src/view/scene.ts`。既存の競技用`src/view/models.ts`の部品を変更する場合は、競技の外見も比較対象に含める。基本は練習専用の腕・脚を使う。

**入出力:** `solveLabPose(state: Readonly<LabState>): LabPose`の呼び口を維持し、新ファイルから再公開する。`LabPose`に犬と人の独立した姿勢、腰、肩・肘・手先、股・膝・足先、犬の足組・支持パッド・4種の持ち手の座標と到達可否を追加する。計算はThree.jsを参照しない。座標は既存の`(s, x, y)`に統一し、描画の`(s, y, x)`への変換は一か所にする。

**実装方針:** 現行の立位をワールド座標で採寸し、腕・脚の全長を変えずに二節へ分ける。肘・膝は逆側へ折れない。犬種共通の支持位置に練習用ベルトと持ち手を置き、見た目の体格に合わせてベルトの取り付けだけを調整する。保持や接地の判定を犬種別の見た目の長さから決めない。`getLabRigPoints(rig)`は実際の描画部品のワールド座標を読み出す検査用関数とする。

- [ ] 先に、技04の犬だけの回転、技34の手と持ち手、技35・36の前足と地面が一致する試験を作る。3犬種×左右の構えで、指定の接触点と表示部品の差が0.01m以下、体・地形へのめり込みが0.01m以内であることを検査する。到達不能な持ち手で成功しない例も入れる。
- [ ] 腰の横移動、膝の曲げ、足を戻す順、手の保持と解除を姿勢へ反映する。手足が届くまで保持・接地イベントを出さない。犬だけが回るときに人を一緒に回さない。ベルト・支持パッドも犬の回転へ追従させる。
- [ ] 手足を伸ばして目標へ強制的に合わせたり、図形の中心に置いた目印だけを測って合格させたりしない。表示上の手先・靴底と、判定側の接触点の両方を測る。
- [ ] `npm test -- tests/lab-pose.test.ts tests/lab-rig.test.ts tests/trick-lab.test.ts` と `npm run typecheck` を通す。代表4技の準備・空中・保持・着地の画像を確認してコミットする。画像の見た目の合格と座標の合格を別に記録する。

## 5. F02 — 移動途中の接触と成立条件を確かめる

**作成:** `src/game/lab-contacts.ts`、`tests/lab-contacts.test.ts`、`tests/lab-boundaries.test.ts`。**変更:** `src/game/trick-lab.ts`、`src/game/trick-lab-terrain.ts`、既存の計算試験2ファイル。

**入出力:** `sampleLabSurface(fixtureId, s)`を維持し、必要な横位置・法線を追加する。`sweepLabContacts(fixture, before, after): LabContact[]`を作る。`before`・`after`は`{atUs, pose: LabPose}`、接触結果は部位・障害物ID・面ID・位置・法線・接触時刻・接触開始／終了・荷重支持開始／終了を区別する。現行`LabContact`の情報を落とさず拡張する。

**時刻の決め方:** 競技の5ミリ秒刻みは変更しない。練習も外側の固定刻みを維持し、その中を入力時刻、最初の接触、支持終了で分ける。外部から渡された描画時刻を新しい計算刻みにはしない。境界の時刻は整数マイクロ秒にそろえ、初めて条件を満たす時刻へ切り上げる。未処理の端数を保持し、8／16／33ミリ秒で進めても同じイベント列にする。

**接触の決め方:** 回転を含む部位の軌跡を調べる。両端だけの直線で判定せず、区間を分け、最初の接触時刻を1マイクロ秒以下の幅まで絞る。側面へ先に当たった場合は失敗とし、犬を横へ移して成功位置に吸着させない。位置を戻す処理が必要な場合も、接触が成立した後の食い込み解消に限定する。両支持は同じ障害物で同時に荷重を受けている時間の共通部分を使う。

同じ時刻では、直前区間の距離・保持時間を積算してから、衝突による失敗、着地・支持の変化、入力の`seq`順、成立の評価の順で処理する。失敗と成功が同時なら失敗を優先する。着地後に足を戻す入力を受けても、その着地を成功へ変えない。

- [ ] 先に、刻みの途中だけの横切り、上面より先の側面接触、支持開始差35ミリ秒だが重なり0、別障害物の越境履歴、前パッド全体が越えていない例を失敗試験にする。レール半幅0.06m・パッド半径0.03mで中心が反対側へ0.07mしか出ていない場合は全体越境にしない。
- [ ] 滑走0.999／1.000／1.001m、片側支持499／500／501ミリ秒、着地前後1マイクロ秒を確認する。0.50秒だけでなく必要距離1.0mも満たす。安定着地は150ミリ秒と0.2mの両条件を維持する。
- [ ] 全38技に成功1例・失敗1例以上を割り当てる。09の回転不足・逆向き・裏返り720°、12の犬270°／人90°での途中キャッチ後に犬360°／人180°で着地、22の45°と0°・90°、29・31の接触と回転の順、32〜38の手・持ち手・解除・足着き順を含める。選択値だけを正解と比較せず、実際の姿勢と履歴で決める。
- [ ] 8／16／33ミリ秒、半速・通常速度、左右をすべて鏡に映した入力で結果を比較する。逆に1条件だけ鏡に映した誤操作は落とす。タイムアウト時も成功を推測しない。
- [ ] `npm test -- tests/lab-contacts.test.ts tests/lab-boundaries.test.ts tests/trick-lab.test.ts tests/trick-lab-terrain.test.ts` と型検査を通し、コミットする。新判定で手本が失敗した場合は地形・入力を修正し、衝突判定を省略しない。

## 13. 試験の範囲と公開判定

| 変更 | 普段の確認 | 候補版の最終確認 |
|---|---|---|
| 計画書・レビュー記録のみ | 差分、相対リンク、参照ファイル・番号・対応表の検査。ゲーム試験を今回実行したとは書かない。 | PRの自動検査結果は別に確認する。 |
| 練習の姿勢・接触 | F01〜F03の計算試験、代表画面試験、型検査 | 全38技・88組、F07、全体検査 |

| 翻訳・共有 | F06の辞書・共有・表示試験、記録保全 | 15言語の巡回、実機での代表表示 |
| 共通描画・保存・時計・配信 | 影響する競技試験まで実行 | 全体検査、確認版の通信・保存分離、実機 |

最終候補では `npm run typecheck`、`npm test`、`npm run build`、`npm run test:e2e` をすべて通す。独立した計算試験と画面試験は別ジョブにできるが、同じ出力ディレクトリを共有しない。通常の変更で無関係な試験を繰り返さず、変更した箇所と共通処理の影響で範囲を決める。既存CIの省略条件を変更する場合は、その変更を専用の差分として検証する。

完了には、各工程の合格資料、独立レビューへの対応、固定コミットの自動検査、iPhone実機の記録をそろえる。実装候補に変更が入った場合は影響する検査をやり直し、新しい確認URLで確かめる。公開後の不具合では候補のコード差分を戻すPRを作り、既存の記録や送信待ちを消して戻す方法は使わない。
